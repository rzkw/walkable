# Fix: `/api/og` returns 500 on Cloudflare Workers (edge runtime)

## Problem

After PR #159 merged and production (`walk-llc.com`, Cloudflare Workers via OpenNext) was redeployed, every `/api/og` request returns `500 Internal Server Error` — including invalid inputs that should return 400 before any network I/O. The project image boxes therefore show no cover images.

Control requests (`/api/definitely-not-real`, `/nonexistent-page-xyz`, `/api/og/nested`) return proper 404s, and the home page serves the new content, so the deployed worker is a fresh build of current `main` with the route registered — but the route module crashes when invoked. The Netlify deploy preview (Netlify Edge runs on Deno) worked.

## Root cause

`app/api/og/route.ts` declares `export const runtime = 'edge'`. The `@opennextjs/cloudflare` adapter (this repo runs 1.19.8) does **not** support the Next.js Edge runtime: it aliases `next/dist/compiled/edge-runtime` to an empty module, so any edge-runtime route builds and deploys silently but 500s at runtime (opennextjs-cloudflare issue #1028). OpenNext Cloudflare docs mandate the Node.js runtime; Workers already run at the edge, so the declaration is unnecessary.

## Fix

Remove `export const runtime = 'edge'` (line 1) from `app/api/og/route.ts`. The route then runs through OpenNext's Node.js runtime path (with `nodejs_compat`). It uses only Web APIs (`fetch`, `URL`, `Response`, `AbortSignal.timeout` — supported at the worker's compatibility date 2025-07-22), so behavior is unchanged.

## Verification

1. `npm run build` passes.
2. Test in the real runtime: `opennextjs-cloudflare build && opennextjs-cloudflare preview` (runs workerd locally — the deferred "test workerd" step). Assert:
   - Terraform-docs post URL → its own cover image
   - `ip route` post URL → its own cover image
   - An older (off-feed) Medium post → `{ image: null }`
   - `evil.com` / missing `url` → 400 `{ image: null }`
3. Deploy with `npm run deploy`, then repeat the same assertions against `walk-llc.com`.

## Not doing

- Upgrading `@opennextjs/cloudflare`: edge runtime is intentionally unsupported (empty shim, still-open issue #1028, docs mandate Node runtime), so an upgrade would not fix the 500; version 1.19.x additionally had a separate regression breaking all dynamic routes on Next 16.2.x (issue #1258). This repo is on Next 16.2.11.
